# PRD: <과제 이름>

> 업무 담당자 인터뷰 전에 아래 질문을 먼저 채울 수 있는 만큼 채우고, 빈칸만 묻는다.
> 질문은 한 번에 3~5개씩, 선택지(A/B/C)를 붙여서 묻는다.

## 1. 배경과 문제
- 지금 누가, 무엇 때문에 불편한가?
- 지금은 이 일을 어떻게 처리하고 있나? (엑셀, 수작업, 기존 시스템)

## 2. 목표
- 이 결과물로 무엇이 달라져야 하나? (한 문장)
- 성공을 무엇으로 판단하나? (숫자 기준이 있으면 숫자로)

## 3. 사용자
- 주 사용자는 누구이고, 얼마나 자주 쓰나?
- 사용자의 기술 수준은? (화면이 필요한가, 결과 파일이면 충분한가)

## 4. 범위
| 반드시 (Must) | 있으면 좋음 (Should) | 이번엔 안 함 (Won't) |
|---|---|---|
| | | |

## 5. 데이터와 입력
- 입력 데이터의 형식, 크기, 출처는?
- 결측값, 이상값, 단위 차이 같은 데이터 품질 문제가 알려진 게 있나?

## 6. 제약
- 반드시 써야 하거나 쓰면 안 되는 기술이 있나?
- 보안, 개인정보, 성능(응답 시간, 데이터 양) 요구는?

## 7. 완료 기준 (Acceptance)
- [ ] 사용자가 <행동>하면 <결과>가 보인다
- [ ] <엣지 케이스>에서 <기대 동작>
- [ ] 테스트: `<명령>` 통과

## 8. 인터뷰 기록
| 질문 | 답 | 반영 위치 |
|---|---|---|
| | | |

## 9. 남은 가정
> 확인하지 못하고 가정한 것. 서술형에서 "왜 이렇게 했나"의 근거가 된다.
