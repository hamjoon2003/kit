# 위험 목록

> 사전 부검(premortem): "이 결과물이 실제 업무에서 실패했다면 이유는?"을 먼저 상상하고 거꾸로 적는다.
> 새 위험이 보이거나 상태가 바뀔 때만 갱신. 서술형의 "약점 → 파급 범위 → 검증 계획" 답이 여기서 나온다.

| # | 약점 / 실패 원인 | 파급 범위 (누가, 무엇이 망가지나) | 조기 신호 | 검증 / 완화 | 상태 |
|---|---|---|---|---|---|
| 1 | | | | | 열림 |

## 점검할 범주
- 입력: 빈 값, 잘못된 형식, 아주 큰 입력, 중복, 단위·시간대 차이
- 정확성: 집계 기준, 경계값(0, 음수, 최대), 반올림
- 운영: 동시 사용, 재시작 시 데이터 유실, 느린 응답, 외부 의존성 장애
- 보안: 입력 검증, 비밀값 노출, 권한 없는 접근
- 유지보수: 하드코딩된 값, 테스트 없는 핵심 로직, 문서와 다른 동작
