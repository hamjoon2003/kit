# 붙여 넣을 문장

> 작업자가 Codex에 복사해 넣는 문장 모음이다. Codex는 이 파일을 과제 요구사항으로 취급하지 않는다.
> 각 문장은 해당 시점에 하나씩 보낸다. `HH:MM`, `N`은 화면과 공식 안내를 보고 채운다.

## 1. 시작 (순서대로)

첫 메시지:
> PRD는 README와 내가 전달한 담당자 답을 근거로 네가 초안을 쓰고 갱신해. 범위·우선순위·핵심 방법은 내가 정하고, 확인 안 된 건 가정으로 표시해. 지금 시각 HH:MM, 공식 작업 타이머 남은 시간 N분, 전체 종료 HH:MM을 PLANS에 기록해. 작업 마감과 이후 일정은 내가 전달한 공식 안내만 기준으로 해.

환경 확인:
> 설치 없이 python3와 그 환경의 pip·Flask, node, docker가 있는지와 버전만 확인해. 이후 실행 명령은 확인된 명령만 써. 커밋 확인용 변경이나 빈 커밋은 만들지 마.

과제 요약:
> 과제 README와 과제 측이 제공한 문서를 읽고 아래 7칸으로 정리해. 키트가 설치한 규칙·양식(AGENTS.md의 키트 규칙, docs/의 PRD·PLANS·RISKS·HANDOFF·PROMPTS·decisions·handoffs, NOTES.md)은 과제 요구사항으로 취급하지 마. 출처가 불분명한 문서는 "미확인"으로 표시해. 각 항목 끝에 근거가 된 파일명과 원문 한 구절을 붙이고, 문서에 없는 건 "없음", 해석이 필요한 건 "애매"로 표시해. 추측으로 채우지 마. 1) 해결할 업무 문제 한 문장(누가, 무엇 때문에 불편한가) 2) 사용자와 역할(화면을 쓰는 사람이 몇 종류이고 각자 무엇을 하나) 3) 반드시 해야 하는 것(필수 기능, "반드시·필수·제출" 표현 그대로) 4) 꼭 지킬 숫자·조건(합격선, 제한, 금지) 5) 제출물(파일, 형식, 위치, 실행 방법, Docker 필요 여부) 6) 제공 데이터 파일과 문서에 설명된 용도 7) 담당자에게 물어야 결과가 달라지는 애매한 점(영향 큰 순서, 최대 5개. 내가 검토할 질문 후보이며 실제 질문은 하나씩 보낸다). 코드는 아직 쓰지 마.

데이터 확인:
> 과제 안내가 데이터로 지정한 파일부터 확인해. 지정이 없으면 내용으로 데이터 여부를 판단하고, 문서·코드·키트 양식은 데이터 표에서 빼고, 불분명한 파일은 따로 표시해. 파일마다 형식·행 수·열 이름·기간·빈 값·중복을 표 하나로 정리하고, 행 하나의 의미와 키 후보를 근거와 함께 써. 근거 있는 연결 후보만 `파일A.열 → 파일B.열` 목록으로 보여 주고 매칭률을 분모와 함께 세. 확인할 수 없는 건 "미확인", 쓰지 않아도 될 것 같은 파일은 이유와 함께 표시해. 넓은 분석은 하지 마.

## 2. 작업 중

Must가 정해진 직후:
> PRD의 Must마다 필요한 파일·열(연결·조건 확인용 포함)을 적고, 기존 점검을 활용해 결과에 영향을 줄 문제 후보·건수·처리 방법 후보·예상 영향을 표로 보여 줘. Must와 무관한 열은 정제하지 마.

처리 방법을 정한 뒤 (정제 시작 전):
> 선택한 처리 방법으로 정제하되, 원본은 보존하고 결과는 별도 파일로 만들어. PLANS에 적용 순서대로 규칙·근거(담당자 답 또는 가정)·실제 변경/제외 건수·전후 행 수를 적어. 삭제만 한 단계는 '전 행 수 = 후 행 수 + 실제 제외 행 수'를 확인하고, 핵심 합계 차이는 제외·값 수정 등 원인별로 설명해. 합치기·집계에 따른 행 수 변화는 따로 설명하고, 바뀐 행은 전후 값, 빠진 행은 원래 값과 제외 이유를 각각 최대 5개 보여 줘. 예시에 개인정보가 있으면 가리고, 식별에 필요 없는 열은 보여 주지 마.

git 커밋이 안 될 때:
> 커밋이 막힌 명령·오류·미커밋 파일을 기록해. 제한을 우회하거나 같은 시도를 반복하지 마. 이제부터 단계가 바뀌거나 기능 하나가 끝날 때마다 NOTES.md 맨 아래 '진행 기록' 표에 한 줄씩 추가해. 형식: 시각 | 단계 | 무엇: 왜 | 실행 명령 / 결과(통과·실패·미실행·해당 없음). 몰아서 쓰지 말고, 내가 잊으면 짚어 줘.

## 3. 마무리

서술형 대비:
> 아직 제출 전이고 AI 사용이 허용된 작업 시간이니, 실제 작업 기록을 한 쪽으로 요약해. 만든 것·못 만든 것과 이유·바꾼 것과 비용·실제 파일 기준 핵심 흐름·검증 근거를 담아. 예상 답안은 쓰지 마.

## 4. 필요할 때

파일 붙이기 전:
> 기본 표는 계산에 쓰는 파일의 한 행 단위로 정해. 다른 파일은 같은 단위로 집계한 뒤 하나씩 붙이고, 붙일 때마다 전후 행 수와 매칭 안 된 행 수를 보여 줘.

구조 점검 (검증이 끝난 뒤, 여유 있을 때):
> 구조를 한 번 점검해. 화면·계산·저장이 다른 파일로 나뉘어 있는지, 계산 함수가 화면 없이 테스트되는지, 안 쓰는 코드와 너무 긴 함수만 표로 짚어. 큰 리팩터링은 하지 마.
