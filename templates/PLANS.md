## 검증표 (요구사항별)
> 기대 결과는 구현 전에, 손으로 확인할 수 있는 작은 예시로 먼저 적는다. 상태: 통과 / 실패 / 미확인.
> 예: 불량률 — 입력 "웨이퍼 10장 중 불량 2장" → 기대 20% → `pytest tests/test_rate.py` → 실제 20% → 통과

## 멈춤 기준
- 같은 오류 2회 반복, 또는 한 단계가 계획 시간의 2배를 넘으면 멈추고 범위를 줄인다. 줄인 내용은 Decision Log에 남긴다.
- 90분 시점: 입력부터 결과까지 한 번 끝까지 도는 최소판이 있어야 한다(엉성해도 됨). 없으면 선택 기능을 빼고 방식을 단순하게 한다. 필수 요구는 임의로 빼지 않고 못 채운 것은 미완료로 남긴다.
- 140분 시점: 새 선택 기능을 시작하지 않고 필수 빈칸·오류 수정·검증·제출 문서·설명 점검에 집중한다.
- 공식 작업 마감 10분 전에는 제출을 시작한다.

## 제출 전 점검 (종료 15분 전)
- [ ] 깨끗한 상태에서 HANDOFF의 실행 명령을 그대로 다시 실행해 결과물이 나온다
- [ ] 보고서·HANDOFF에 적은 숫자가 방금 다시 실행한 결과와 같다
- [ ] 검증표의 Must 행이 모두 "통과"이거나, 아니면 이유가 위 "위험"에 "남긴 채 제출"로 있다
- [ ] PRD가 요구한 제출 파일이 모두 작업 공간에 있고 저장됐다 (편집기 탭에 저장 안 된 표시 없음)
- [ ] (저장·수정 기능이 있으면) 같은 입력 재실행·입력 변경·재시작 뒤 이전 결과와 저장이 어떻게 되는지 확인했다
- [ ] 키·비밀번호가 파일에 없다
- [ ] 제출한 뒤 화면에서 제출 완료 상태를 직접 확인했다 (제출 버튼을 누른 것만으로 끝내지 않는다)
